# Independent audit, 2026-11-06

Four independent reviewers and two blind re-labellers worked on the hold-out result and the system after it was published. They were read-only on the repository (the robustness tester worked on a copy). What they found is recorded here, including what is not yet fixed. Their raw scripts were kept outside the repo.

## 1. Are the labels trustworthy? (blind re-label)
A Sonnet agent, given 60 random hold-out claims (24 false, 16 true, 10 borderline, 10 not-in-filings) and the filings but no labels, agreed with the original Haiku labels on 54 (90%). On the 50 where both gave true/false, 48 agreed. All 30 originally-false claims it saw were confirmed false. The six disagreements: four "not decidable" vs "false" (derived measures a company does not report), two borderline-true vs false (0.2% and rounding on Walmart's revenue definition). Labels are still agent-labelled; the human spot-check (`docs/SPOTCHECK.md`) is blank.

## 2. Leakage and process integrity
Not found: arms touching hold-out data before the freeze (all 144 hold-out cache keys are timestamped after the tag), the labeller using the truth store or XBRL (0 mentions across 1,274 labels; every number in every excerpt is in the filing text), labels edited after commit, source changes between freeze and run end.
Found: tuning exposure (hold-out labels existed, and per-memo false counts were seen, before the last tuning commit; the 80-case synthetic set and extractor gold contain figures of hold-out companies; literal overlap with hold-out claims is small, 11 of 491); the judges were never tuned while the engine had three dev rounds; the judge prompt tells the model to say "unchecked" for measures not in the table; post-hoc changes (scoring, headline metrics, rule 2b). The README now states the process exactly.

## 3. Reporting honesty (independent recomputation)
Every reported number reproduces exactly. Corrected after the review: coverage column (now any-matching-quote: 89/89/83%, not 87/71/65%); control counts (15 memos, 192 true claims, not 197); the borderline-included reading (engine 18/84 true flagged against 15 and 23: advantage disappears) and flagged 397/471 vs 408; the paid-run honest-control result (engine 4/15 vs 1/15) now in DEFEND and README; "picture is the same" removed; repeatability claim narrowed to the deterministic decision step; the matcher caveat (an independent matcher puts the same-family judge 1.5 to 3.5 points ahead); the miss description (about 25 of 36 non-extracted misses are in-scope claims). The "named" win is partly an output-format effect.

## 4. Robustness of the system (hands-on, on a copy)
- Tests 70/70; mutation testing 44 mutants, 37 killed by pytest (including the gate). `og gate` alone kills 25. Surviving mutants (untested behaviour): January 52/53-week fiscal-year rule, mandate side check, limit price overriding the quote, percent-vs-fraction margin heuristic, reviewing a non-held run, empty-memo check, coverage numerator.
- Truth store: 12 of 12 random rows match the 10-K text; a sweep of 739 rows found no mismatches (15 unmatched, all explained: restated originals, Netflix in thousands). Later reclassifications count as restatements (a truthful memo quoting the original can be "stale").
- Edge cases that behave badly: loss-growth percentages are blocked (negative base); duplicated claims inflate the coverage line; a zero-width space silently drops a claim; rounded figures ("$15 billion" for 15.51) are blocked by the 2% cap; "calendar 2024" for a January year-end is blocked; a null ticker is treated as the traded company.
- **Security-relevant, not fixed:** (a) the review page's approve button needs no credentials (the page attaches the admin token itself), so anything that can reach the port can approve a held order; (b) a lowercase ticker plus a tiny `limit_price` (or an `as_of` before the first synthetic quote) clears an order over the notional cap, because the quote lookup is case-sensitive and the agent's limit price becomes the sizing price; (c) the agent chooses `as_of`, so it can backdate to a date when a figure was not yet superseded; (d) an empty memo or model outage produces a held order with no claims (reviewer flooding); (e) on-demand refresh for a ticker not in `companies.json` raises a swallowed `KeyError`, so refresh-and-recheck does nothing for unseen companies; (f) an agent can bisect the share cap from status alone; (g) prompt injection was only simulated, and none of the 18 extractor-gold memos has a recorded answer under the current prompt.
- Real ports could not be bound in the sandbox, so the gateway was tested in-process.

## 5. Does the benchmark match how the system will be used? No, not yet.
Ranked gaps: (1) base rate: native memos hold a median 13 false claims, real agent memos 0 to 2, and the honest sample is 15 memos written from the store's own table (circular); (2) the production path (MCP gateway, mandate, hold and review, order mapping) is not benchmarked at all; (3) no adversarial or injected content, and the agent controls `as_of` and `limit_price`; (4) errors are gross (median 21% off), so subtle or deliberate errors are untested; (5) claim types never present: rumours, guidance, quarterly, price, segment, non-US; (6) one `as_of` for all memos, restatements exercised on 2 claims; (7) all 25 companies preloaded, so on-demand fetching is untested; (8) one recorded extractor sample per prompt, so variance is invisible; (9) labels agent-only. Numbers that would not transfer: the 88% and 85% rates, the 7% honest-stop rate, the 100% memo stop, the dev-set 54/55 and 25/25.
