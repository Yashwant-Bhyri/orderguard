How it works

How OrderGuard decides every order

Your limits are enforced in code, so no model can approve an order. Models can only make a decision stricter.

  1. MandateSigned

    You sign the limits

    Choose the symbols, order sizes, daily budget, price band, and the size above which a person has to approve. The mandate is signed with your key, so no agent or model can quietly loosen it.

  2. All checks pass

      Every order is checked

      Each order is valued at a trusted market price, not the price the agent quotes, and checked against your mandate in microseconds.

    • Stopped

      Risk

      The swarm is watched as a whole

      A risk model scores each approved order against what every other agent is doing, so it sees one position split across several agents, a loop resending the same order, or an agent that suddenly acts out of character.

    • Review queueby expected loss

        Risky orders go to a person

        Held orders arrive in a queue ranked by how much money is at stake, with the reasons attached. Your team approves or rejects them, and any incident can be replayed in simulation.

        Decision adapter

        of unsafe mandate drafts flagged on held-out cases

        Post-trained on an underlying decision model. It answers specific questions with calibrated probabilities: does this order match what the agent said it would do, does this mandate suit its stated purpose, and how urgently should a person look at this hold.
